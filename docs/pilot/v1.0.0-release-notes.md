## Architecture: session-ID ownership model

Core mechanism (per `v1.5-session-model.md` § "The model"): the WI table
carries a `session_id` ownership token; claim is an atomic CAS on aihub
(set-if-empty AND status claimable); same-machine recovery keeps the
session_id and increments `spawn_n`; cross-machine takeover atomically
swaps it; terminal ops clear it; bounded fail lands in blocked with the
session cleared. Industry research confirmed the family: ownership
epoch + fencing-on-use (ZooKeeper sessions, K8s UID replacement) — let
every daemon keep its credentials, make the server reject writes from a
session that is no longer current.

Three mandatory additions (fable BLOCKER findings, non-deletable — each
guards an already-paid-for failure):

- **B1 pre-claim durable journal** — `{wi_id, session_id}` written durably
  before the CAS call; startup replays it. Crash safety for the
  claim-crash gap (D5) and the CAS retry-idempotency anchor.
- **B2 flush fence = (session_id, spawn_n) dual key** — every derivation
  gets a monotonic spawn_n; the flush envelope carries both; a flush is
  accepted only if session matches AND spawn_n is current. Replaces the
  v1 adoption-window fence (F16's successor).
- **B3 identity/credential split** — session_id is the secret push
  credential; public surfaces see only a derived sha256-prefix
  fingerprint. The agent never sees the session_id (only PF_SPAWN_N and
  PF_SESSION_HANDLE); push credentials travel via one-shot GIT_ASKPASS.

## Migration summary

From v1 (per `v1.5-session-model.md`): **deleted** the owner_generations
table and the entire generation/attempt/instance lineage,
generation-scoped credential mint/revoke, the adoption-window fence, and
the claim/resume/takeover intent trichotomy. **Preserved** (verified by
review as clean): recovery cascade internals, six-layer process cleanup,
transcript sync to capsule git, observe per-WI monitoring (all 8
channels), backpressure + same-error retry cap, answer relay, agent
spawn isolation, git hooks, the verification evidence gate (V4),
gitlink local precheck (V8), budget, async commit+push, and the
capsule/execution.json/work-item.json model.

Legacy library migration: a read-only rehearsal against the real
production PostgreSQL (`docs/pilot/v1.5-migration-rehearsal-report.md` —
2666/2666 terminal WIs, 3760 memories, idempotent pass-2, 0 FAIL lines)
surfaced five cutover-scale gaps (per-project seq semantics, CJK goal
cap, memory rebuild at scale, list-page cap, idempotency reporting), all
fixed same-day. The real cutover (`docs/pilot/v1.0.0-cutover-report.md`)
then imported the frozen production library: **3057/3057 tickets +
3739/3739 memories**, per-project seq preserved, CJK content byte-exact,
pass-2 fully idempotent, legacy container retained for rollback.
