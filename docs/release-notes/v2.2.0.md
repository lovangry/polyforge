# Polyforge v2.2.0

A simplification release: dead mechanisms and routes are removed, the
workspace yaml grammar is narrower, and several recovery paths now share
one rule. Read "Upgrade" and "Breaking changes" before deploying.

## Upgrade

- aihub's legacy DB migrations were removed. Upgrade only from **v2.1.0 or
  later**. A database that was never opened by v2.1.0 is not supported.
- Re-check every `cli.toml` and `.polyforge.yaml` against the changes below;
  both now fail loudly on the old shapes.

## Breaking changes

### cli.toml

- Unknown top-level keys are now an error (previously ignored).
- The `url` alias for `server` is removed; use `server`.

### .polyforge.yaml

The only section is now `models`, keyed by project:

```yaml
models:
  polyforge:
    default: ["model-a", "model-b"]   # every step of the project
    code: ["model-c"]                 # one step kind (qa, spec, author, code, gate, review)
```

- The old `projects:`, `workflow_defaults:` and `release:` sections are
  refused.
- Precedence for a step: `pf submit --models` (see below) > project kind list >
  project `default` > workflow
  step `model_candidates` > workflow defaults. A project `default` therefore
  overrides even steps that pin their own models.
- The file is validated before the claim. An invalid file is refused with
  `DAEMON-414`; the work item stays queued for other machines, and auto-pull
  skips that project.

### Manual model candidates: `pf submit --models`

- `pf submit <id> --models a,b,c` sets a candidate list for that work item;
  it is the candidate chain of EVERY step of the work item, with the same
  advance-on-model-failure and gate-fail-reset behavior as any other list.
- Model-candidate precedence, highest first: `--models` > `models.<project>.<kind>`
  in `.polyforge.yaml` > `models.<project>.default` > the workflow step's own
  `model_candidates` > the workflow's `defaults.model_candidates`.
- Local to the machine: nothing is stored in aihub. The list is validated
  (non-empty, spaces trimmed, no empty id, no duplicate), persisted with the
  daemon's pending submit queue, and recorded in the capsule's `capsule.json`
  (`manual_candidates`), so a daemon restart, recovery, and `pf resume` of a
  blocked work item (which re-claims from the capsule chain) keep using it.
  Auto-pulled work items have no manual list.

### Clone source

Claims clone only from the repo URLs registered in aihub. Every project must
have its repos registered, e.g. `pf projects patch <project> --repos name=url[,name=url...]`.
The local-checkout clone source (`projects:` in the yaml, `DAEMON-415`) is gone.

## Removed

- `repair_pending` and `DAEMON-517`. A work item whose capsule is missing, or
  whose project is no longer mapped, at daemon restart is now aihub `blocked`
  with a reason note. `pf resume` re-claims it and resumes from the
  checkpoint. A restart that finds the capsule missing for a work item
  wrapped mid-seal now also ends `blocked`.
- `DAEMON-415`, `rotate-secret`, and the project identifier / rotate-identifier.
- Routes: `/progress`, GET session, GET ship-ledger, POST memories/search,
  memory list/patch, the daemon `/jobs/{wi}/observe`, `abandon-repair`,
  `close-auth`.
- Ready-queue executable segments (collapsed into one).
- `pf answer --answer-id` (`--question` remains).
- The `canceled` session-end verdict.
- The `PI_SESSION_DIR` environment variable (pi reads `PI_CODING_AGENT_SESSION_DIR`).

## Behavior changes

- Model switching follows the cause of death: only model-class failures
  (`model_error`, `model_hung`, `step_timeout_slow_model`, `exit_model_class`)
  advance the candidate; host-class exits block; anything else retries the
  same model. Interrupted attempts never advance the candidate.
- Event bodies no longer carry `fault_class`; the cause of a failed attempt is recorded as `failure_cause` on that attempt in `execution.json`.
- The aihub git hook requires the `session-fingerprint` push option on
  proxied pushes.
- A clone failure is always `DAEMON-516` and the claim is abandoned.
- Recovery never re-pins the workflow bundle; a missing claim snapshot blocks
  the work item.
- The daemon heartbeat reports the real build version.
- Atomic file writes are unified in one package.
- `GET /work-items` clamps an explicit `limit` to 1000.

## Fixed

- A later step's transcript could overwrite step 1's transcript; transcripts
  now sync per dispatch only.
- Timing races in the e2e tests under CPU load.
