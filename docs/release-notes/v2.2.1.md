# polyforge v2.2.1

Installer and harness-integration fixes. No server, daemon or CLI behavior change; the aihub and pf binaries differ from v2.2.0 only in their version stamp. Upgrade by re-running `tools/install.sh`.

## Fixed

- **Claude-only machines now get a daemon.** `tools/install.sh` keeps its own checkout of the release tag at `~/.local/share/polyforge/release/<version>` (stable symlink `release/current`, swapped atomically; the previous version is kept, older ones pruned) and starts the daemon with `-workflows-dir ~/.local/share/polyforge/release/current/workflows`. The workflows no longer come from pi's package directory, which only existed on machines with pi.
- **Claude Code is set up independently of pi.** Machines with pi installed previously never had their Claude skill updated. The skill directory is now replaced wholesale (no stale files), and the SessionStart hook is registered once in `~/.claude/settings.json` at the stable path `~/.claude/skills/polyforge/hooks/claude-session-start.sh` (backup written only when the file changes). `statusLine` is never modified; the installer prints the snippet for the progress line.
- **pi is pinned to the binary's tag.** The installer reads the polyforge entry in pi's `settings.json` and runs `pi install git:git@github.com:silgrid/polyforge.git@<version>` when it is not at the same tag as the pf binary (pi replaces the existing entry in place).
- **The chat id is visible in Claude Code.** The SessionStart hook prints a JSON object: `systemMessage` shows `polyforge chat id: <id>` in the terminal, `additionalContext` gives it to the model. Previously plain stdout reached only the model.

## Upgrade notes

- The installer is idempotent: a second run changes nothing.
- A daemon already running with a different `-workflows-dir` is not restarted automatically; the installer prints an `ACTION:` line. When the pf binary is upgraded the installer stops the daemon first and restarts it with the new path itself.
- `PF_BIN` (default `/usr/local/bin/pf`) overrides the binary path.
